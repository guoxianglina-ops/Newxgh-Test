象过河仓库管理系统

XiangGuoHe WMS  |  版本 v2.13  |  2026 年 7 月

一、项目概述

象过河仓库管理系统是一款面向中小型仓库的 Web 端管理软件，覆盖采购管理、销售管理、库存管理、财务管理、审核流程、会员管理等 20+ 业务模块。系统采用纯静态前端 + 后端 REST API 的架构，支持电脑端管理与手机扫码快速出入库两种工作场景。

技术特点

  • 零依赖纯前端：不依赖 React/Vue 等框架，一个 wms-core.js（约 4700 行）驱动整个系统
  • 前后端分离：前端通过 GET/POST /api/data 进行全量数据读写，支持乐观锁版本控制
  • 混合模式：有网络走后端 API，无网络自动降级到 localStorage 本地存储，离线也能继续工作
  • ID 预分配池：前端一次申请 50 个 ID 号段，多客户端同时操作不冲突
  • 响应式设计：同一套代码适配桌面浏览器和手机浏览器，手机版有独立的触控优化 UI

颜色 / 尺码服装行业专用：颜色组、尺码组管理

3.2 采购管理

  • 采购订单 → 采购入库 → 自动更新库存 + 创建批次 + 生成溯源链路
  • 采购退货 → FIFO 批次消耗 + 库存扣减
  • 付款结算：支持 PDF 附件上传，已付/未付状态追踪

3.3 销售管理

  • 销售订单 → 销售出库 → 自动扣减库存 + FIFO 出库批次消耗 + 溯源链路追加
  • 销售退货 → 自动退回库存 + 创建新批次 + 继承原始链路
  • 收款结算：收款状态实时追踪

3.4 库存管理

  • 批次管理：每次入库创建独立批次，记录来源单号、数量、单价、剩余库存
  • 全链路溯源：每件商品从采购订单到销售出库的完整流转记录可追溯
  • 库存流水：所有库存变动（入库/出库/退货/调拨）均有流水记录
  • 库存预警：低于安全库存线自动提醒
  • 仓库盘点：系统数量 vs 实际数量对比，自动生成盘盈盘亏单
  • 库存调拨：跨仓库调拨，源仓库扣减 + 目标仓库新增批次
  • 已结算批次：已全部出库完毕的批次归档管理

四、产品设计思路

4.1 问题发现

中小仓库普遍使用纸质单据或 Excel 管理库存，存在以下痛点：

  • 出入库操作繁琐：员工需要走到电脑前手动录入
  • 数据不同步：电脑端和手机端数据不互通
  • 溯源困难：出了问题很难追溯到具体哪一批次、哪个环节
  • 多角色协作混乱：制单人、审核人、主管之间缺乏清晰的状态流转

4.2 解决方案

  • 扫码出入库：将二维码贴在商品/货架上，员工用手机扫码即可快速创建出入库单，不需要走到电脑前
  • 全链路溯源：每一批商品从采购下单到销售出库的完整路径均可追溯，出现质量问题时可以精准定位
  • 审核状态机：草稿 → 待审核 → 已审核 → 驳回 → 重提，每个状态变更有明确的权限和日志
  • 混合离线模式：网络断开时自动降级到本地存储，网络恢复后自动同步，保证仓库作业不中断

4.3 功能优先级决策

在开发过程中，我对功能进行了优先级排序：

  • P0 必须有：商品管理、入库出库、库存查询 — 没有这些系统跑不起来
  • P1 效率提升：二维码扫码、Excel 批量导入、审核流程 — 核心差异化功能
  • P2 锦上添花：生产管理、BOM、租赁维修等 — 满足不同行业客户的扩展需求
  • P3 未来规划：数据看板/仪表盘、微信小程序端、报表导出

六、Excel 批量导入设计

针对仓库管理员经常需要批量录入数据的场景，设计了完整的 Excel 导入流程：

  • 动态表头识别：不限制用户 Excel 的列名和列序，系统自动扫描前 5 行匹配已知列名（支持 10+ 中文别名变体）
  • 四级商品匹配：ID 精确匹配 → 名称精确匹配 → 名称模糊匹配 → 编号匹配，逐级降级确保最大匹配率
  • 全字段未匹配报告：商品、仓库、供应商、客户各自独立检查，一次性报告所有未匹配项
  • 行级编辑：导入后支持逐行编辑数量/单价/仓库等字段，修改后自动重新匹配
  • 去重与持久化：上传时自动识别重复行并标记，数据存入 localStorage 刷新不丢失

七、接口文档与前后端协作

作为产品经理角色，我完成了以下后端交接工作：

  • 编写了完整的数据实体定义文档（涵盖 20+ 业务实体、40+ 字段表）
  • 设计了 REST API 接口规范：GET/POST /api/data（全量存取 + 乐观锁）、POST /api/id/allocate（ID 预分配 + 原子操作）
  • 定义了审核状态流转逻辑和角色权限矩阵
  • 整理了后端交接文件夹（含接口文档 Markdown/Word、前端源码、测试 Excel 样例）
  • 将前端代码中的 Supabase 依赖抽象为通用 API_BASE_URL 占位符，后端切换时只需改一个变量
