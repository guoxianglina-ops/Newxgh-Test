## 项目迭代规范

每次完成新需求或 bug 修复后，按以下流程操作：

1. **修改 `index.html`**：直接在 `index.html` 上完成所有代码变更。
2. **验证语法**：用 `node -e "new Function(script)"` 验证 JS 语法无错误。
3. **建立新版本文件**：语法通过后，将 `index.html` 另存为 `vX.Y.Z.html`，命名严格遵循版本号规则。
4. **更新版本号和变更日志**：修改版本号标识 + 在 `版本更新日志v2.md` 最上方追加新版本条目。
5. **保留旧版本文件**：旧版本 `.html` 文件必须保留在 `新系统` 目录下，不可删除，以便出 bug 时快速回滚。
6. **全部工序完成后**：所有代码变更和文档修改都完毕，不再有任何待修改内容后，关闭所有旧浏览器窗口，用谷歌 Chrome 打开两个新窗口，一个登录 1 号账号（张三），一个登录 0 号账号（审核员/主管），供用户手动验证。

**⛔ Chrome 打开后立即停止** — 不运行任何 Bash、不 echo、不 TodoWrite、不文件校验、不空回复。任务完成=停止。

**⛔ Bash 重试硬上限** — 所有 Bash 命令（包括 echo、node -e、文件校验等）**最多连续执行 3 轮**。3 轮后无论结果，**立即永久终止 Bash 工具调用**，禁止无上限循环重试。如果 3 轮仍无法确认结果，直接告知用户当前状态，等待用户指示。

**⛔ 强制停工规则**（全局硬限制，优先级最高）：
1. Bash 类工具（echo / node 脚本校验）单任务连续调用次数上限 = 3；
2. 命中 3 次阈值后，禁止发起新 tool_call、禁止新建 Bash 会话，立刻输出终止总结，等待人工下发新任务；
3. 无视历史业务待办、Todo 条目残留的"未完成"判定，达到次数阈值强制停工。

**⛔ 后续所有任务规则前置约束**：发起任何 Bash/Node 工具调用前，必须先读取本文档完整内容，对照项目规范（Bash 最多连续执行 3 次、禁止无限 echo 循环、Chrome 打开后立即停止）校验合规性；规则不满足则不准发起 Shell 命令。禁止偷懒跳过读取文件。
